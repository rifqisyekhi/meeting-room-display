1. Identitas & Tujuan Sistem

Sistem ini dirancang khusus untuk mengotomatisasi pemakaian, pemesanan, dan publikasi status ruang rapat di lingkungan Biro Keuangan dan BMN Kemnaker RI:

  • Display Publik Interaktif (/display atau /): Tampilan TV cerdas di luar ruangan rapat yang menyajikan status ruangan secara realtime (Tersedia / Sedang Digunakan), hitung mundur sisa durasi rapat, jadwal rapat berikutnya, jadwal sholat otomatis, running text dinamis, serta QR Code presensi.
  • Portal Pengajuan Mandiri (/booking): Form pemesanan ruangan bagi pegawai dengan validasi bentrok jadwal, fasilitas pendukung, peserta, dan materi rapat.
  • Dashboard Terpadu (/dashboard): Panel kendali bagi Admin Utama dan Pimpinan untuk approval, emergency cancel, manajemen ruangan, manajemen user (RBAC), serta analitik utilisasi.
  • Presensi Mandiri QR/Barcode: Fitur check-in otomatis peserta menggunakan scanner kamera atau handheld barcode di pintu ruangan rapat.
  • Integrasi Eksternal: Sinkronisasi dua arah Google Calendar API v3 dan WhatsApp Notification Bot (SISKA).

4. Alur Hidup Rapat (Meeting Lifecycle)

1. User Booking (/booking) → Status: Menunggu Approval → 2. Approval Pimpinan

• Jika Disetujui: Status: Akan Datang / Segera → Masuk Jam: Berjalan (Layar TV Merah & QR Aktif) → Presensi Scan QR → Selesai (End Time / Checkout)

• Jika Ditolak: Status: Ditolak (Alasan dikirim via WA)
• Jika Situasi Mendesak: Status: Dibatalkan (Emergency Cancel)

5. Skema Tabel Basis Data (PostgreSQL)

  • rooms: id (PK), name (UNIQUE), location, capacity, status ('Tersedia'/'Sedang Digunakan'/'Pemeliharaan'), facilities (JSONB), images (JSONB), img.
  • users: id (PK), name, username (UNIQUE), email, dept, role, status ('Aktif'/'Nonaktif'), password_hash (scrypt salt:hash).
  • roles: name (PK), description, permissions (JSONB), is_system (BOOLEAN).
  • meetings: id (PK), google_id, title, agenda, requester, booked_by_username, room_name, date, start_time, end_time, status, participants, approved_by, rejection_reason, checked_in_at, checked_in_by, check_in_method, checked_out_at, attendees (JSONB), materials (JSONB).
  • reviews: id (PK), meeting_id, room_name, user_name, rating (1-5), comment, admin_reply.
  • notifications: id (PK), meeting_id, type, title, message, status, read_by (JSONB).

6. Hukum Mutlak & Larangan Koding (Commandments)

DILARANG KERAS MENGEMBALIKAN dummyDB DI FRONTEND!
Seluruh proses otentikasi harus memanggil backend API POST /api/dashboard/login. Backend mengamankan password menggunakan crypto.scryptSync. Jangan pernah meng-hardcode akun pengguna di komponen React.
  • Wajib Menjaga Auto-Seeder: Fungsi seedDefaultData() di backend/src/services/dashboard.service.js tidak boleh dihapus. Fungsi ini menjamin akun master siap pakai di laptop setiap developer yang melakukan git pull.
  • Validasi Bentrok Jadwal: Ruangan yang sama pada rentang jam dan tanggal yang sama tidak boleh disetujui lebih dari satu kali jika jadwalnya bertabrakan.
  • Git Workflow Tim: Kerjakan tugas di branch masing-masing. Lakukan update dari main dengan git pull origin main. Dilarang melakukan git push --force ke branch main.
  • Integritas .gitignore: File backend/data/dashboard-store.json dan file .env tidak boleh di-push ke Git. Selalu gunakan template .example.
